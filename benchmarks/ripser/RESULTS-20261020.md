# ripser vs ripser++ -- the benchmark tables of 2026-10-20

The raw tables of the head-to-head between `canns_lib.ripser` and
[ripser++](https://github.com/RustParallel/ripser) on the 1200x1200 ASA
matrix and on the 97 real grid-cells matrices.

**WHERE THEY LIVE.** The tables themselves are NOT in this repository:
`.gitignore` excludes `benchmarks/ripser/results/` ("# Benchmark
results"), so the raw data stays out of the history. The delivery
directory holds both the scripts and the tables, and this file is the map
between them -- the table, what it holds, and which checker guards it.

**The CSVs are the only data source.** `RIPSER-BENCH-20261020.md` (in the
delivery directory, next to the tables) is a view of them: every number in
the report can be pointed at a row of one of these tables, and each table
has a checker that recomputes the verdicts and carries negative
self-tests, so a table that has been edited by hand cannot pass.

The benchmark runs on a remote host (the machine does the work; the local
checkout only carries the code). `../build_and_h2h.sh` builds the
comparison sites; the `check_*.py` scripts below are the checkers.

## Reading the barcode comparison

An md5 of the bar values is **not** comparable across the two
implementations: ripser++ prints its intervals with 6 significant digits,
so its values carry up to ~5e-6 relative rounding against ours. The
comparison is therefore numeric -- exact equality of the per-dimension bar
counts plus a greedy nearest-neighbour match of the bars with a 1e-5
relative tolerance. The md5 columns are over OUR full-precision bars only,
so they are regression fingerprints for our own runs.

Where the two sides disagree, a third implementation (GUDHI 3.13.0) is run
on the same matrix as an oracle, and the verdict records who it agrees
with. The verdict vocabulary is closed:

- `SAME_BARCODE` -- the two sides agree on every bar;
- `ORACLE_SUPPORTS_OURS` -- they disagree, and GUDHI agrees with us;
- `ORACLE_SUPPORTS_RIPSERPP` -- they disagree, and GUDHI agrees with
  ripser++ (a failure: we would be the odd one out);
- `BARCODE_MISMATCH` -- they disagree and no oracle settled it (a failure).

## Reproducing

```bash
# on the benchmark host, with the two builds installed as "sites"
python nsfix_ab.py       --out nsfix_ab.csv
python clean_h2h.py      --out clean_h2h.csv
python filtration_sweep.py --out filtration_sweep.csv
python validate_gridcells.py --site <site> --cells 0 --out gridcells_validation.csv

# the checkers
python check_nsfix_ab.py nsfix_ab.csv
python check_clean_h2h.py clean_h2h.csv
python check_filtration_sweep.py filtration_sweep.csv
python check_validate_gridcells.py gridcells_validation.csv --self-test
python check_bounds_ab.py bounds_ab.csv --gridcells bounds_gridcells_ab.csv --self-test
python check_standard_bench.py standard_bench.csv --self-test
python check_gridcells_bench.py gca_results_final.csv --self-test
```

Every checker prints the denominator it computed itself and the names of
the cells that are missing, so a partial table cannot be read as a
complete one.
